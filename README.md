# 深海养殖水质时序建模平台

本项目是**本机浏览器运行的单一平台**。左侧导航只有「模型训练」「数据分析」「未来预测」三个模块；无需账号、云服务、CDN 或前端构建工具。实际训练和预测由 Python/PyTorch 执行，界面通过本机 FastAPI 服务访问，不上传到外部服务器。

## 启动平台

1. 在 `F:\project\深海养殖风险与决策` 安装 [uv](https://docs.astral.sh/uv/) 并运行 `uv sync --python 3.10`。首次安装 PyTorch 可能需要较大下载量。
2. 双击 `启动工具.cmd`。脚本直接使用本项目的 `.venv\Scripts\python.exe`，不依赖资源管理器能否找到 `uv`。
3. 程序会在本机 `127.0.0.1` **自动选择可用端口**并打开浏览器；命令窗口会打印 `Platform address: http://127.0.0.1:端口/`。若浏览器未自动打开，将该地址复制到浏览器。关闭命令窗口即停止平台。

也可从项目目录运行 `uv run --python 3.10 python main.py`。如果启动失败，命令窗口会保留错误信息；不要直接打开 `web/index.html`，因为它需要本机 API 提供真实数据与模型。

## 观测文件

支持 UTF-8/GB18030 编码的 CSV 和 XLSX。必须包含：

```text
timestamp,site,depth_m,temperature_c,dissolved_oxygen_mg_l
```

`timestamp` 是时间，`site` 是观测序列标识，`depth_m` 是采样水深（m），水温单位 ℃，溶氧单位 mg/L。程序按序列标识和水深分别组织历史窗口；单条序列须时间唯一、等间隔、无缺口，同一模型内的序列采样间隔须一致。带时区的记录统一换算到 UTC；未标时区的记录保留输入时钟值并按 UTC 解释，因此导入前应统一时区。缺测、重复、单位不符或不规则采样须先核对数据，不会被悄悄插值。单个上传文件最大 50 MiB。

## 可直接上传的实测测试数据

`sample-data/nerrs_dry_bar_2013_train.csv` 为 **900 条**沿海河口水温和溶氧实测记录；`sample-data/nerrs_dry_bar_2013_holdout.csv` 为紧接其后的 **300 条**独立时间段记录。两份文件均为同一个观测序列 `apadbwq`，时间间隔 15 分钟，未插值。先在「模型训练」上传 train 文件，可用历史窗口 **24**、预测步数 **6**、训练轮数 **3** 试运行；再在「数据分析」上传 holdout 文件并选择所保存模型；「未来预测」沿用该 holdout 文件即可。

数据来自 [NOAA NERRS SWMP Apalachicola Bay Dry Bar 站](https://www.fisheries.noaa.gov/inport/item/47713)，由 [SWMPr 公开样例压缩包](https://s3.amazonaws.com/swmpexdata/zip_ex.zip) 提供；[2013 年站点元数据](https://cdmo.baruch.sc.edu/waf/YearlyFiles/Apalachicola/water%20quality/metadata/apawq01-12.13m.pdf) 说明仪器位于约 2 m 水深站点、离底约 0.3 m。文件中的 `depth_m=1.7` **仅为按此推算的名义分组深度**，随潮汐变化的逐时实际水深并非恒定。采用源文件中水温与溶氧均标记 `<0>` 的连续记录，并增加数值合理性筛选；时间按 SWMP 固定 GMT−5 转为 UTC。原样例为 provisional-plus 记录，`<0>` 仅表示通过初始质控。完整来源、处理、时间段与哈希见 `sample-data/nerrs_dry_bar_2013_source.json`；转换脚本为 `scripts/prepare_swmp_sample.py`。

**地域与用途边界：**这是美国佛罗里达河口牡蛎场附近的水质记录，不是渤海湾或鲑鳟网箱数据；只能用于测试平台的导入、模型训练及预测流程，不能用于推断目标海域的适养性。正式引用原数据还应按 NOAA 的要求注明监测站和来源。

## 三个模块

### 模型训练

上传历史观测文件，核对行数、时间范围、采样间隔及每条观测序列。设定历史窗口、未来预测步数与训练轮数（窗口、步数是**采样步**，并非固定小时）。启动后台训练后可看到进度；页面不需要等待 HTTP 请求一直占用。每条序列按时间划分训练、验证和测试段（70% / 15% / 15%），预处理均值与标准差仅由训练段拟合。展示两项变量在验证/测试段的 MAE，并与沿用最后一次观测的基线比较。

模型与预处理参数保存在 `workspace/models/<模型编号>/` 的 `model.pt` 和 `metadata.json` 中。两者必须一起保留：后者记录输入特征、历史窗口、预测长度、采样间隔、归一化参数和评估指标。上传文件及清单也只保存在本机 `workspace/datasets/`，下次打开平台仍可选用。

### 数据分析

导入需要分析的**已有历史观测**，选择已保存模型及观测序列。平台按训练时的窗口与预处理参数逐窗口回放，将**预测长度最后一步**与对应时刻的真实值比较，展示历史曲线、模型曲线、MAE、末值基线及明细，并可导出完整 CSV。若导入区间与模型训练用数据重叠，该回放误差**不是独立验证结果**；请以模型训练页的留出测试指标及后续独立观测共同判断模型表现。

### 未来预测

选择模型、观测文件和序列后，以最新连续观测作为输入，按模型保存的预测时距输出未来水温与溶氧。页面区分实测与模型输出，展示时间序列与数值，可下载 CSV 或含模型评估记录的 Excel。新数据沿用训练时的特征顺序和标准化参数，预测时**不会重新训练模型或重新拟合预处理**。

## 结果边界与验证

平台不根据短时温氧预测自动给出藻华、风暴或场址适宜性结论。平均误差较小也不等于已经完成独立极端事件预警或证明干预有效。项目没有渤海湾实测数据；附带的美国河口记录仅用于功能测试。开发验证已使用临时合成序列及上述真实记录走通导入、训练、历史回放、未来预测和导出；测试模型没有作为渤海湾研究成果保留。
