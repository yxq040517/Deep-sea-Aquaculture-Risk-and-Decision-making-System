# 深海养殖水质时序建模平台

本项目是**本机浏览器运行的单一平台**。左侧导航只有「模型训练」「数据分析」「未来预测」三个模块；无需账号、云服务、CDN 或前端构建工具。实际训练和预测由 Python/PyTorch 执行，界面通过本机 FastAPI 服务访问，不上传到外部服务器。

## 启动平台

1. 在 `F:\project\深海养殖风险与决策` 安装 [uv](https://docs.astral.sh/uv/) 并运行 `uv sync --python 3.10`。首次安装 PyTorch 可能需要较大下载量。
2. 双击 `启动工具.cmd`。脚本直接使用本项目的 `.venv\Scripts\python.exe`，不依赖资源管理器能否找到 `uv`。
3. 程序会在本机 `127.0.0.1` **自动选择可用端口**并打开浏览器；命令窗口会打印 `Platform address: http://127.0.0.1:端口/`。若浏览器未自动打开，将该地址复制到浏览器。关闭命令窗口即停止平台。

也可从项目目录运行 `uv run --python 3.10 python main.py`。如果启动失败，命令窗口会保留错误信息；不要直接打开 `web/index.html`，因为它需要本机 API 提供真实数据与模型。

## 观测文件

支持 UTF-8/GB18030 编码的 CSV 和 XLSX。必须包含：

```text
timestamp,site,depth_m,temperature_c,dissolved_oxygen_mg_l
```

`timestamp` 是时间，`site` 是观测序列标识，`depth_m` 是采样水深（m），水温单位 ℃，溶氧单位 mg/L。程序按序列标识和水深分别组织历史窗口；单条序列须时间唯一、等间隔、无缺口，同一模型内的序列采样间隔须一致。带时区的记录统一换算到 UTC；未标时区的记录按 UTC 解释。可附带 `F_Temp`、`F_DO_mgl` 等原始质控列，平台只统计标记出现次数，不擅自解释其含义或修改观测。上传时填写来源、时区说明、传感器水深依据和质控说明；未填写会明确显示“未提供”。时间重复、缺测与不规则采样会在导入失败时显示诊断，不会自动插值；来源时区备注不会替你转换时间。溶氧百分饱和度不能冒充 mg/L，必须依据原始资料先完成有依据的换算。单个文件最大 50 MiB。

## 可直接上传的实测测试数据

`sample-data/nerrs_dry_bar_2013_train.csv` 为 **900 条**沿海河口水温和溶氧实测记录；`sample-data/nerrs_dry_bar_2013_holdout.csv` 为紧接其后的 **300 条**独立时间段记录。两份文件均为同一个观测序列 `apadbwq`，时间间隔 15 分钟，未插值。先在「模型训练」上传 train 文件，可用历史窗口 **24**、预测步数 **6**、训练轮数 **3**，选择“按时间顺序留出”；再在「数据分析」上传 holdout 文件并选择所保存模型；「未来预测」沿用该 holdout 文件即可。此样例只有一个日历年，不能用于“完整日历年独立留出”。

数据来自 [NOAA NERRS SWMP Apalachicola Bay Dry Bar 站](https://www.fisheries.noaa.gov/inport/item/47713)，由 [SWMPr 公开样例压缩包](https://s3.amazonaws.com/swmpexdata/zip_ex.zip) 提供；[2013 年站点元数据](https://cdmo.baruch.sc.edu/waf/YearlyFiles/Apalachicola/water%20quality/metadata/apawq01-12.13m.pdf) 说明仪器位于约 2 m 水深站点、离底约 0.3 m。文件中的 `depth_m=1.7` **仅为按此推算的名义分组深度**，随潮汐变化的逐时实际水深并非恒定。源文件水温与溶氧均标记 `<0>` 的连续记录才进入样例，`F_Temp` 和 `F_DO_mgl` 原始标记列仍随文件提供，平台会显示其频次；还进行了数值合理性筛选。时间按 SWMP 固定 GMT−5 转为 UTC。原样例为 provisional-plus 记录，`<0>` 仅表示通过初始质控。完整来源、处理、时间段与哈希见 `sample-data/nerrs_dry_bar_2013_source.json`；转换脚本为 `scripts/prepare_swmp_sample.py`。

**地域与用途边界：**这是美国佛罗里达河口牡蛎场附近的水质记录，不是渤海湾或鲑鳟网箱数据；只能用于测试平台的导入、模型训练及预测流程，不能用于推断目标海域的适养性。正式引用原数据还应按 NOAA 的要求注明监测站和来源。

## 三个模块

### 模型训练

上传历史观测文件，核对行数、时间范围、采样间隔、来源、探头深度依据、原始质控标记及缺测诊断。设置历史窗口、未来预测步数与训练轮数（窗口、步数是**采样步**，并非固定小时）。默认按各序列时间顺序划分训练/验证/测试段（70%/15%/15%）；可选“完整日历年独立留出”，要求所有序列至少覆盖三个可用日历年：末年作测试、前年作验证、更早年份作训练，不符合条件即报错，不自动退回默认模式。预处理均值与标准差仅由训练段拟合；页面展示各段年份/时间范围、水温和溶氧 MAE 与末值基线 MAE。模型若未优于基线会有提示，但低 MAE 本身不能证明可预警。

模型与预处理参数保存在 `workspace/models/<模型编号>/` 的 `model.pt` 和 `metadata.json` 中。两者须一起保留：后者记录输入特征、时间窗口、采样间隔、归一化参数、时间切分依据、训练源 SHA-256 及评估指标。上传文件及来源/质量清单只保存在本机 `workspace/datasets/`，下次打开平台仍可选用。旧数据或旧模型缺乏相应来源记录时会显示“未知”，不能推定为已验证。

### 数据分析

导入**已有实测历史数据**，选择已保存模型和观测序列。平台按训练时的窗口与预处理参数逐窗口回放，将**预测长度最后一步**与对应时刻的真实值比较，展示曲线、MAE、末值基线和明细。可选填注明来源及适用条件的水温上限（℃）和/或溶氧下限（mg/L），进一步显示命中、误报、漏报的采样步数及事件段、实测与预测累计超限时长差；没有实测事件时召回率显示“无法计算”，不假装为 100%。平台检查文件指纹和同序列时间范围，分别标注“时间不重叠”“时间重叠”或“独立性未知”；时间不重叠也不是跨场址验证。可导出完整回放 CSV；以上规则只是用户提供的管理限值，不是内置鱼体安全线。

### 未来预测

选择模型、观测文件和序列后，以最新连续观测为输入，按保存的预测时距输出未来水温与溶氧。页面区分实测与预测值，可下载 CSV 或含来源与管理限值的 Excel。选填注明来源的温度上限、溶氧下限及措施执行所需时间，可查看预测的首次越限时间、**相对末次实测**的名义提前量及扣除数据滞后后在**报告生成时**还剩多少时间；若使用 2013 年测试数据，预测时刻早已过期，页面会明确标识“不能作为当前行动依据”。没有预测越限只表示当前预测窗口内未触发用户规则，并不表示安全。新数据沿用训练的特征顺序和归一化参数，不会重新拟合或重新训练。

## 结果边界与验证

平台不根据短时温氧预测自动给出藻华、风暴或场址适宜性结论。生理限制氧饱和度与 mg/L 浓度不能直接互换；用户提供的限值既不是整个鲑鳟类通用耐受线，也不能替代海况与人员可达性。低平均误差、局部事件识别和措施净效应分别需要独立证据。项目没有渤海湾实测数据；附带的美国河口记录仅用于功能测试。开发验证已使用临时合成序列及该真实记录走通导入、训练、历史回放、未来预测和导出；测试模型没有作为渤海湾研究成果保留。
